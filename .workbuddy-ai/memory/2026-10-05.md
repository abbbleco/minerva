## Startup crash fix (after the "feeds, ideas, goals" commit f95e5269)

The backend failed to boot with a nested `fastapi.routing.merged_lifespan`
traceback. Root cause: Phase 2's feeds work added `methods_feeds as _methods_feeds`
to `tui_gateway/server.py`'s `from . import (...)` block and its `_m.register`
tuple, but `tui_gateway/methods_feeds.py` was never created → `ImportError` at
import. The trailing `NameError: _flush_sessions_before_exit` in the atexit
callback was fallout (module never finished importing).

Fixed by reverting those two lines — feeds is an HTTP REST surface
(`web_routers/feeds.py` + desktop `hermesApi`), no `feeds.*` RPC method is
called anywhere, so the module would be speculative infrastructure.

Verified: lifespan enters; real `uvicorn.Server` boots and serves
`/openapi.json` 200 with the 10 `/api/goals` paths; all 46 relative modules
referenced by `tui_gateway/server.py` exist; 11-module import smoke OK.

Lessons:
- `tests/tui_gateway/test_tui_gateway_server.py` imports `tui_gateway.server`, so
  it catches this at import — **run the tui_gateway suite before committing**
  changes to that package.
- The editable install (`%LOCALAPPDATA%\hermes\installs\…\workspace`) is a stale
  2026-10-03 snapshot; a dev run loads **repo code with that venv's packages**
  (which is why a repo-only bug surfaces with installed-venv paths in the
  traceback). A packaged/installed launcher needs a re-provision to pick up repo
  changes.

## Running the desktop dev app (`pnpm dev`)

`cd apps/desktop && pnpm dev` (pnpm 12.8.1, workspace at repo root; `dev` =
`concurrently -k "npm:dev:renderer" "npm:dev:electron"`). Confirmed working
end-to-end: vite renderer on 127.0.0.1:5174, Electron (DevTools 9222), and the
backend spawned **from the repo** (`[backend] 'serve' supported for Minerva source
at …\MinervaV2`) → `HERMES_BACKEND_READY`. The live backend serves all 10
`/api/goals` routes; `/api/goals` returns 401 (auth-gated) and `/openapi.json`
200.

Two **sandbox-only** workarounds were needed (the user's own terminal does not
need either):
- `ELECTRON_RUN_AS_NODE=1` is injected into this shell, which makes `electron .`
  run as plain Node → `SyntaxError: The requested module 'electron' does not
  provide an export named 'BrowserWindow'`. Fix: `unset ELECTRON_RUN_AS_NODE`.
- The sandbox has no usable GPU → Chromium GPU process dies with
  `exit_code=-1073741819` (0xC0000005) and `FATAL: GPU process isn't usable`.
  Fix: `HERMES_DESKTOP_DISABLE_GPU=1` (the app's own switch; forces software
  rendering + `--no-sandbox` sticky fallback).

Pre-existing issues surfaced (NOT caused by the premium-features work):
- Renderer floods `Maximum update depth exceeded … getSnapshot should be cached`
