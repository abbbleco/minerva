`scripts/build/web.mjs` typecheck failed with 2 errors in `web/src/App.tsx`:
- `TS6133: 'canUpdateMinerva' is declared but its value is never read` (line 950)

**Fix:** `web/src/App.tsx:1004` `if (canUpdateHermes)` -> `if (canUpdateMinerva)`.
One-line change. Verified with `tsc -b tsconfig.app.json --force` -> exit 0.

## Reusable triage knowledge for this repo's desktop/CI typecheck

- The desktop bundle typechecks `web` via the TS **solution builder** over
  `web/tsconfig.json` (references `tsconfig.app.json` + `tsconfig.node.json`).
- `tsc -p . --noEmit` in `web/` is a **no-op**: `web/tsconfig.json` has `"files": []`,
  so it silently reports success. Use `tsc -b` (or `tsc -b tsconfig.app.json --force`)
  to actually check anything. Do not trust the `--noEmit` form as verification.
- `tsc -b` does NOT abort on the first failing project; it reports all projects' errors.
- **Local-vs-CI resolution gotcha:** the local `web/node_modules` contains an extra
  nested `@vitejs/plugin-react` (6.0.3) that the lockfile does not have (lock hoists it
  to root `node_modules/@vitejs/plugin-react`; root has NO `@rolldown/plugin-babel`).
  From the nested copy, `@vitejs/plugin-react/types/optionalTypes.d.ts` resolves
  `@rolldown/plugin-babel` -> real types -> phantom `TS18048: 'preset.rolldown.filter'
  is possibly 'undefined'` at `web/vite.config.ts:11`. In CI's clean `npm ci` layout that
  import degrades to `any`, so no error. **That error is a local artifact, not a CI
  blocker — do not "fix" vite.config.ts for it.** Reinstalling web deps per the lockfile
  would clear it (avoided here: limited WiFi data).

**Touched:** `web/src/App.tsx` (1 line).

## Fixed CI failure #2: release handoff fetch ("No files selected from release handoff")

**Symptom:** `desktop-bundle-smoke.yml` step "Fetch one exact downloadable artifact"
failed in 2s:
`ValueError: No files selected from release handoff` (raised at
`scripts/releases/handoff.py:259`).

**Root cause:** incomplete artifact-name rebrand. `handoff._fetch_receipts` filters the
receipt's file paths with `fnmatch` against the workflow's `--include` pattern. The smoke
workflow hardcoded `product=HermesBundled` (line 118) → pattern
`HermesBundled-*-win-x64.msix`. But the build actually emits `MinervaBundled-*`, so every
file was filtered out and `selected` stayed empty.

Ground truth obtained by executing the real identity module
(`MINERVA_DESKTOP_VARIANT=bundled node -e require('./apps/desktop/product-identity.cjs')`):
`artifactNamePascal=MinervaBundled`, `appId=co.abbble.minerva-bundled`,
`msixAppIdWithOrg=Abbble.MinervaBundled`. `electron-builder.config.cjs:87` interpolates
`${artifactNamePascal}-${version}-${os}-${arch}.${ext}`, so the staged file really is
`MinervaBundled-<version>-win-x64.msix`. `product-identity.cjs` (documented as "THE single
source for every name-shaped value") was rebranded; its consumers were not.

**Fix (same bug class, sibling call paths included)** — `HermesBundled`→`MinervaBundled`,
`HermesLight`→`MinervaLight`:
- `.github/workflows/desktop-bundle-smoke.yml` — `product=` (the failing step)
- `.github/workflows/desktop-bundled-release.yml` — msixbundle fetch glob, `single()`
  glob, and the assembly-version regex (would have failed at the next step)
- `scripts/releases/darwin.py` — mac feed URL prefix in `merge_mac_feeds` (mac stable
  release would raise "Missing native ZIP")
- `scripts/render-builds-table.py` — `_ASSET_RE`, `parse_assets`/`table_rows` keys,
  `_COMMIT_EXPECTED` patterns (public downloads table + commit page)
- `scripts/stage-msixbundle.mjs` — stale comment only
- coupled tests: `tests/ci/test_desktop_bundle_smoke.py` (also fixed the stale MSIX
  identity fixture `NousResearch.HermesBundledCanary` → `Abbble.MinervaBundledCanary`,
  since `release_artifacts.py:294` compares the baked bundle `Name` to `msixAppIdWithOrg`),
  `tests/ci/test_commit_build_staging.py`, `tests/scripts/test_release_darwin.py`,
  `tests/scripts/test_release_artifacts.py` (shares `_inputs` from test_release_darwin),
  `tests/scripts/test_render_builds_{binding,publication}.py`

**Not changed on purpose:** `NousResearchInc.HermesAgent` (store `identityName`, explicitly
retained until the ABBBLE Store account lands); name-agnostic/opaque fixtures in
`test_release_r2.py`, `test_stable_release.py`, `test_upload_summary.py`,
`test_release_channels.py`, `test_channel_build_versions.py` and the `apps/desktop/scripts/*.test.mjs`
stubs (verified they feed name-agnostic code, so they still pass).

**Verification:** pure syntax check on all 8 edited Python files (no bytecode written) —
all OK; `git diff` reviewed line by line. Tests/build NOT run locally (no pytest; and the
build must only run on GitHub — see MEMORY.md).
